### 阅读「✎ 续一章」：应用内续写

- 用户选定「应用内按钮」而不是定时任务：书页底部一键，由浏览器直连中转站生成下一章，只存本机
- 改法：
  - 书页底部 `data-act="read-next"` 按钮；首次点击先出 key 输入框（`#readKeyInput`，密码型），存 `hedgehog:relay` 后直接开生成
  - `genChapter()` POST `https://eazydata.org/v1/messages`，头带 `x-api-key` / `anthropic-version: 2023-06-01` / `anthropic-dangerous-direct-browser-access: true`，模型 `glm-5`，`max_tokens 2500`
  - `readGenPrompt()` 拼书名、人物（名+中文名+年龄+身份）、全书情感线、上一章尾部 1200 字，要求 3 段 × 90–130 词、双人在场、尺度止于暗示、只出 JSON
  - `readParseChapter()` 去代码块围栏、取首尾花括号、校验 passages 的 text+zh，标题截 40 字
  - 成功后追加到 `hedgehog:kinder-read-gen`，`route()` 重绘并滚到新章；失败把 `接口 4xx · 原因` 写在面板上，key 不动可再点
  - 状态挂 `READ_GEN{busy,book,err}`，重绘后不丢；生成中输入框自动收起
  - 版本：第一刀 v44 / `v2026-11-27.1`，本刀 v45 / `v2026-11-27.2`
- **未实测**：真机/真 key 的直连生成（本机环境变量里是本地代理 token，直连 eazydata 返 401 `Invalid token`），接入请求体已在测试里打桩核对
